# Maplet Folder Share Link — Specification for Website Integration

This document is the ground-truth reference for building the `maplet.net/share` website
(the Universal Link landing page) so it can decode links generated by the Maplet iOS app.
It covers the URL format, the exact byte-for-byte encode/decode pipeline, a verified worked
example, reference JavaScript decode code, and the Apple App Site Association (AASA) setup
required for "Open in App" behavior.

There are **two** link formats in the wild. The app itself always generates the new
(compressed) format, but old links shared before this migration used the legacy format and
must keep working forever, so the website should ideally support decoding both.

| | Legacy (pre-2026) | Current (new) |
|---|---|---|
| Scheme | `maplet://` (custom scheme, **no website involved**) | `https://` (Universal Link) |
| Host / path | `import` | `maplet.net/share` |
| Payload encoding | Standard Base64 (JSON, uncompressed) | Base64URL (JSON, minified + zlib/deflate-compressed) |
| Example | `maplet://import?data=eyJmb2xkZXJOYW1lIjoiVHJpcCIsLi4ufQ==` | `https://maplet.net/share?data=bY_BTsMwEER...` |
| Reaches the website? | **No** — this scheme has no associated domain, so it only ever opens directly in the app (if installed) and otherwise fails silently. | **Yes** — this is a real HTTPS URL, so it always loads the website; iOS then hands off to the app via Universal Links if installed. |

Because legacy links never touch a webpage, **the website practically only needs to handle
the current format**. The legacy section below is included for completeness/reference only
(e.g. if you ever want a "paste an old link" text box on the site).

---

## 1. Current format — URL structure

```
https://maplet.net/share?data=<payload>
```

- Exactly one query parameter: `data`.
- `<payload>` is a Base64URL string (see §2) of a zlib/deflate-compressed (see §3), minified
  (see §4) JSON object describing one folder and its locations.
- There is no versioning field today. If the schema changes in a backward-incompatible way in
  the future, a new query param (e.g. `v=2`) should be introduced rather than reusing `data`.
- Typical link length: **~250–500 characters** for a folder with 1–30 locations (well under
  browser/OS URL limits). An empty/minimal folder is ~150 characters.

---

## 2. Base64URL encoding (RFC 4648 §5, unpadded)

The `data` value uses **URL-safe Base64 with padding stripped**, so it never needs
percent-encoding when placed in a query string:

- `+` → `-`
- `/` → `_`
- `=` padding is removed entirely.

To decode: reverse the two character substitutions, then re-add `=` padding until the string
length is a multiple of 4, then Base64-decode normally. Any standard Base64URL decoder
(`atob` after substitution, Node's `Buffer.from(s, 'base64url')`, Python's
`base64.urlsafe_b64decode` after re-adding padding, etc.) works fine.

---

## 3. Compression — ⚠️ raw DEFLATE, NOT zlib-wrapped

**This is the single most important gotcha.** The app uses Apple's `Compression` framework
with the `COMPRESSION_ZLIB` algorithm identifier. Despite the name, this does **not** produce
an RFC 1950 zlib stream (2-byte header + Adler-32 trailer) — it produces a **raw RFC 1951
DEFLATE stream** with no header and no checksum. This was verified directly: the first bytes
of a real compressed payload are `6d 8f ...`, which is not a valid zlib CMF/FLG header
(a real zlib stream would start with `78 xx`), and standard `zlib.decompress` fails on it with
"incorrect header check". Decompressing the exact same bytes with **raw inflate** (no
wrapper) succeeds and reproduces the original JSON exactly.

**Practical implication:** you must use your library's *raw* inflate mode, not its normal
zlib/gzip mode:

| Environment | Correct call |
|---|---|
| Node.js | `zlib.inflateRawSync(buffer)` (NOT `zlib.inflateSync`) |
| Browser / `pako` | `pako.inflateRaw(bytes, { to: 'string' })` (NOT `pako.inflate`) |
| Python | `zlib.decompressobj(wbits=-15).decompress(data)` (NOT `zlib.decompress`) |
| Go | `flate.NewReader(r)` (NOT `zlib.NewReader`) |

When *encoding* (if the website ever needs to generate its own share links, e.g. from a
"create on web" feature), use the matching raw-deflate compressor (`pako.deflateRaw`,
`zlib.deflateRawSync`, `zlib.compressobj(wbits=-15)`, etc.) so the app can decode it — the app
side only knows how to `compression_decode_buffer` with `COMPRESSION_ZLIB`, which expects this
same raw-deflate framing.

## 4. Minified JSON schema

Before compression, the folder is serialized as JSON with **short, minified keys** (not the
natural Swift property names) to shrink the payload. Optional fields are **omitted entirely**
when empty/false/nil rather than being present with an empty value — always treat a missing
key as "use the default", not as an error.

### Folder object (top level)

| Short key | Full meaning | Type | Required? | Notes |
|---|---|---|---|---|
| `fn` | folder name | string | always present | |
| `fi` | folder icon | string | always present | SF Symbol name, e.g. `"star.fill"`, `"folder"`. **Not renderable on web as-is** — see §6. |
| `fc` | folder color | string | always present | Hex color, e.g. `"#FF6B35"` (with leading `#`). |
| `sd` | shared date | integer | always present | Unix timestamp in **seconds** (not milliseconds) — `Date(timeIntervalSince1970:)` on the Swift side. |
| `l` | locations | array of location objects | always present | May be an empty array. Currently capped at **30 items** per folder by the app (older shares may have up to 15, links can't exceed 30 today). |

### Location object (each entry in `l`)

| Short key | Full meaning | Type | Required? | Notes |
|---|---|---|---|---|
| `ti` | title | string | always present | |
| `la` | latitude | number | always present | Rounded to 6 decimal places (~11cm precision) before encoding. |
| `lo` | longitude | number | always present | Same rounding as latitude. |
| `c` | category | string | always present | Freeform string, not a fixed enum. Built-in app defaults are `"Food"`, `"View"`, `"Shopping"`, `"Other"`, but users can create custom categories with arbitrary names — don't assume a closed set. |
| `v` | isVisited | boolean | omitted if `false` | Only present (and `true`) when the location was marked visited. Absence = `false`. |
| `n` | notes | string | omitted if empty/absent | |
| `a` | address | string | omitted if empty/absent | |
| `lm` | landmark name | string | omitted if empty/absent | |
| `ci` | city | string | omitted if empty/absent | |
| `s` | state | string | omitted if empty/absent | |
| `co` | country | string | omitted if empty/absent | |
| `tz` | time zone | string | omitted if empty/absent | IANA identifier, e.g. `"Asia/Dubai"`. |
| `t` | telephone number | string | omitted if empty/absent | |
| `cp` | contact person | string | omitted if empty/absent | |
| `r` | rating | integer | omitted if absent | 1–5 when present. |

### TypeScript type for reference

```typescript
interface SharedFolderPayload {
  fn: string;           // folder name
  fi: string;            // SF Symbol icon name
  fc: string;            // hex color, e.g. "#FF6B35"
  sd: number;             // unix seconds
  l: SharedLocation[];
}

interface SharedLocation {
  ti: string;             // title
  la: number;             // latitude
  lo: number;             // longitude
  c: string;              // category (freeform)
  v?: true;               // present+true only if visited; absent = false
  n?: string;             // notes
  a?: string;             // address
  lm?: string;            // landmark name
  ci?: string;            // city
  s?: string;             // state
  co?: string;            // country
  tz?: string;            // IANA time zone
  t?: string;             // telephone number
  cp?: string;            // contact person
  r?: number;             // rating 1-5
}
```

## 5. Worked example (verified end-to-end)

This exact example was generated using the app's real Swift encoding pipeline and independently
verified to decode correctly using raw-deflate inflate + Base64URL decode in Python — use it as
a test vector for your decoder.

**Input folder:**
- Name: `Dubai Trip`, icon: `star.fill`, color: `#FF6B35`, shared: `2026-01-15 12:00:00 UTC` (`1768478400`)
- Location 1: "Burj Khalifa" at `25.197197, 55.274376`, category "View", visited, rating 5, with notes/address/city/state/country/timezone/phone all set.
- Location 2: "Local Falafel Spot" at `25.204849, 55.270782`, category "Food", not visited, no optional fields.

**Minified JSON (post-minify, pre-compression — 454 bytes):**


## 6. Reference JavaScript decoder

Using [`pako`](https://www.npmjs.com/package/pako) (works in both browser and Node):

```javascript
import pako from 'pako';

function base64UrlToUint8Array(base64url) {
  let base64 = base64url.replace(/-/g, '+').replace(/_/g, '/');
  while (base64.length % 4 !== 0) base64 += '=';
  const binary = atob(base64); // or Buffer.from(base64, 'base64') in Node
  const bytes = new Uint8Array(binary.length);
  for (let i = 0; i < binary.length; i++) bytes[i] = binary.charCodeAt(i);
  return bytes;
}

function decodeMapletShareLink(url) {
  const parsed = new URL(url);
  const data = parsed.searchParams.get('data');
  if (!data) return null;

  const compressed = base64UrlToUint8Array(data);
  const json = pako.inflateRaw(compressed, { to: 'string' }); // RAW deflate, not inflate()
  const payload = JSON.parse(json);

  return {
    folderName: payload.fn,
    folderIcon: payload.fi,
    folderColor: payload.fc,
    sharedDate: new Date(payload.sd * 1000), // seconds -> ms
    locations: (payload.l || []).map(l => ({
      title: l.ti,
      latitude: l.la,
      longitude: l.lo,
      category: l.c,
      isVisited: l.v === true,
      notes: l.n ?? null,
      address: l.a ?? null,
      landmarkName: l.lm ?? null,
      city: l.ci ?? null,
      state: l.s ?? null,
      country: l.co ?? null,
      timeZone: l.tz ?? null,
      telephoneNumber: l.t ?? null,
      contactPerson: l.cp ?? null,
      rating: l.r ?? null,
    })),
  };
}
```

Node.js equivalent without `pako` (built-in `zlib`):

```javascript
import { inflateRawSync } from 'zlib';

function decodeMapletShareLinkNode(url) {
  const data = new URL(url).searchParams.get('data');
  const buf = Buffer.from(data, 'base64url'); // Node understands base64url natively
  const json = inflateRawSync(buf).toString('utf8');
  return JSON.parse(json);
}
```

Run either function against the worked example in §5 to sanity-check your implementation
before wiring up real UI.

## 7. Legacy format (reference only — not expected to reach the website)

`maplet://import?data=<payload>` where `<payload>` is **standard Base64** (not URL-safe, may
contain `+`, `/`, `=`) of the **uncompressed, full-key** JSON:

```json
{
  "folderName": "Trip",
  "folderIcon": "folder",
  "folderColor": "#007AFF",
  "sharedDate": "2026-01-15T12:00:00Z",
  "locations": [
    {
      "title": "...", "latitude": 0, "longitude": 0, "notes": null, "category": "...",
      "address": null, "landmarkName": null, "city": null, "state": null, "country": null,
      "timeZone": null, "telephoneNumber": null, "contactPerson": null,
      "isVisited": false, "rating": null
    }
  ]
}
```

Note `sharedDate` here is an **ISO-8601 string** (via `JSONEncoder`'s default `Date` strategy),
unlike the new format's Unix-seconds integer. If you ever add legacy support to the website,
decode with standard Base64 (`atob`/`Buffer.from(x, 'base64')`) and no decompression step —
straight to `JSON.parse`.

Because `maplet://` has no associated domain, these links can **only** open directly in the
app (if installed) — a browser has no way to route them to `maplet.net`, so the website will
essentially never receive one in practice unless a user manually pastes the raw text into a
future "import via pasted link" text box.

## 8. Universal Links / Apple App Site Association (AASA)

For `https://maplet.net/share?...` links to open directly in the Maplet app on iOS (instead of
just showing the webpage), the domain must host an AASA file, and the app's entitlements must
already reference the domain (already done on the app side — see below).

- **App side:** `com.apple.developer.associated-domains` entitlement includes
  `applinks:maplet.net`.
- **Bundle identifier:** `com.Gemshi.Maplet`
- **Apple Team ID:** `BT4K8UQD9N`

**Website side (still needed):** host the following at
`https://maplet.net/.well-known/apple-app-site-association` (served as
`application/json`, **no redirects**, valid TLS, no file extension):

```json
{
  "applinks": {
    "apps": [],
    "details": [
      {
        "appIDs": ["BT4K8UQD9N.com.Gemshi.Maplet"],
        "components": [
          { "/": "/share", "comment": "Matches the folder-share landing page" },
          { "/": "/share/*", "comment": "Matches /share with any trailing path segments" }
        ]
      }
    ]
  }
}
```

Use the modern `appIDs` (array) + `components` syntax above, **not** the older `appID`
(singular string) + `paths` syntax. Apple introduced `components` in iOS 13 and it's now the
preferred/recommended format — it matches on path (`/`), query (`?`), and fragment (`#`)
individually and supports an `exclude: true` flag, whereas the legacy `paths` array only does
simple wildcard string matching. iOS 13+ ignores `paths` entirely whenever `components` is
present in the same `details` entry, so there's no benefit to including both unless you
specifically need to support iOS 12 devices (in which case add a `paths` key alongside
`components`, but never mix `paths` and `components` within the same `details` entry — use
separate entries with duplicated `appIDs` if you need both).

Notes for the website implementation:

- The AASA file must be reachable **without a redirect** and over HTTPS with a valid cert.
- iOS fetches this file when the app is installed/updated, not on every link tap — so changes
  can take a little while to propagate to devices, but this only needs to be set up once.
- Even with AASA configured correctly, iOS Universal Links only auto-open the app under normal
  taps (not e.g. long-press "Open" context menus, and not always from within some in-app
  browsers like certain chat apps). The website **must always work standalone** as a fallback,
  since some fraction of taps will land on the webpage even with the app installed.
- Recommended page behavior at `/share`:
  1. Parse and decode `data` client-side per §4–§6.
  2. Render a preview (folder name/icon-fallback/locations) so the link is useful even without
     the app (e.g. for desktop visitors, or users who don't have Maplet).
  3. Show an "Open in Maplet" button that (a) relies on the OS having already tried the
     Universal Link handoff, and (b) as a manual fallback, can attempt
     `maplet://import?data=<same-payload-re-encoded-legacy-or-just-reuse-this-URL>` — in
     practice, simply re-attempting `location.href = window.location.href` or a dedicated
     "Open App" button that also links to `https://maplet.net/share?...` again works, since iOS
     will hand off on a fresh user-initiated navigation.
  4. Show a "Get Maplet on the App Store" link/button for users without the app installed.

## 9. Other gotchas / FAQ

- **Coordinate precision:** lat/lng are rounded to 6 decimals (~11cm) by the app before
  encoding — don't be surprised if they don't exactly match the "real" saved value to the last
  floating-point digit.
- **`fi` (folder icon) and location `c` (category) icons don't map 1:1 to web assets.** `fi` is
  an SF Symbol name (Apple's icon font — not available on web). The website has no icon data
  for categories either (only the category *name* string is transmitted, not its icon/color).
  Recommend either (a) maintaining your own small lookup table for the ~4 built-in category
  names (`Food`/`View`/`Shopping`/`Other`) and falling back to a generic pin icon for anything
  else (including custom user categories), or (b) just using one generic marker icon and
  showing the category as a text label/badge.
- **Empty/missing optional fields mean "not set", not an error.** Always code against "key may
  be absent" rather than "key is present with null/empty string".
  **Location limit:** the app currently caps shared folders at **30 locations**; links with
  more locations than that simply won't exist (the app truncates before generating the link),
  so you don't need to defensively handle "too many locations" beyond basic array bounds
  safety.
- **No signature/auth on the payload.** Anyone can hand-craft a `data` value, so treat decoded
  content as untrusted user input on the website (escape when rendering, validate types before
  use, etc.) — same as you would for any query-string-driven page.
- **This spec covers the folder-sharing link only.** Maplet has a separate `.maplet` file
  import mechanism (file extension based, handled entirely in-app) that is unrelated to this
  URL scheme and irrelevant to the website.
